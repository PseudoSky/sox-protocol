# Migration plan: SOX Protocol plugin architecture (v1)

## Intro

- **Goal:** Make SOX Protocol's middleware framework actually pluggable end-to-end. Pipeline becomes the only path to BackingStore in both transports; a manifest-driven plugin contract (4-kind 2-axis taxonomy + capability flags) is frozen in spec; out-of-tree plugins discoverable via Python entry-points with allowlist-gated loading; one reference plugin (`schema-strict`) migrates real existing code (`routes._validate_body`) out of `core/`; TS SDK ships a contract spike (types + stub Pipeline) to lock the cross-language shape; conformance harness's client-side identity substitution is deleted in the same commit as the legacy CI matrix entry.
- **ROI:** high (canonical). Quantitative: HTTP conformance from 22/10/27 → 32/0/27; ~21d sequential v1 plan compressed to ~13d sequential / ~10d parallel (38% / 52% reduction); one fewer engagement on critical path; ~22 inline `_validate_body` call sites removed; `PassthroughIdentityResolver` deleted; `tools/conformance_runner.py:805-813` deleted (the program's symbolic milestone). Qualitative: cross-language plugin ecosystem unblocked; framework moves from "architecturally correct but unwired" to "real, not aspirational"; supply-chain boundary hardened via `--allow-plugins` allowlist; observability surface (`pipeline_trace`) makes plugin-induced failures debuggable from request artifact alone.
- **Phases:** 7 sub-engagements (6 v1 + 1 post-v1) totalling 31 sub-engagement phases. This master plan tracks the 7 sub-engagements as Phases P1–P7; per-sub-engagement phase prompts are generated by `sox-cto-system:planner` when each sub-engagement's `01-plan` actually dispatches.
- **Current status:** not started
